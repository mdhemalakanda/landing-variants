Question 1 WooCommerce 19 November 2026

WooCommerce Coupon Validation Message

Client’s original question

“Kirjoita kupongin koodi, ole hyvä” appear, when haven’t done anything with code. When this suppose to show up?

What does this message mean?

“Kirjoita kupongin koodi, ole hyvä” is the Finnish translation of WooCommerce’s standard validation message: “Please enter a coupon code.”

This message comes from WooCommerce itself, not from our custom plugin.

When should this message appear?

Under WooCommerce’s standard behavior, this message should appear only when someone submits the coupon form without entering a coupon code.

For example:

  • The customer opens the coupon section.
  • They leave the coupon field empty.
  • They click the “Käytä” button or press Enter while the field is empty.

WooCommerce then displays this validation message to explain that a coupon code must be entered first.

Should it appear automatically?

No. A normal page load should not trigger this validation message on its own.

The coupon validation is triggered when the coupon form is submitted. If the message appears without anyone submitting the form, that behavior should be investigated separately.

How does our current coupon section work?

We have also updated the coupon section’s visibility:

  • Initially, only “Onko sinulla etukoodi?” is visible.
  • Clicking that text reveals the coupon input field and the “Käytä” button.
  • Clicking it again hides the coupon form.
  • The existing coupon success and error notifications remain functional.

This visibility change does not modify WooCommerce’s built-in validation message.

Can we change the wording?

Yes. If needed, we can customize the validation message to use a more natural Finnish sentence:

Kirjoita ensin etukoodi kenttään.

Meaning: “Please enter the coupon code in the field first.”

This is an optional wording improvement, not an implemented change. The existing WooCommerce message remains unchanged unless we decide to customize it.

Important clarification

The coupon box visibility change and WooCommerce’s coupon validation are two separate things.

Our plugin controls the coupon section’s custom display behavior and wording elements. WooCommerce handles the built-in empty-coupon validation.

Implementation status

  • Coupon section visibility behavior Updated
  • Custom Finnish validation wording Proposed — not yet implemented
  • WooCommerce validation message Unchanged

Question 2 WooCommerce 19 November 2026

Changing WooCommerce Order Email Texts

Client’s original question

“How to change WooCommerce email text to users? Other option if you can send all messages to me, will manually edit and send to improved versions.”

Which parts of an email can be edited in the admin?

Every email under WooCommerce → Settings → Emails has a “Hallinnoi” (Manage) button. That page allows editing:

  • Subject (Aihe) — the title line of the email.
  • Heading (Otsikko) — the large title shown inside the email.
  • Additional content (Lisäsisältö) — a short free-text paragraph at the end of the email.
  • Enable/disable and, for admin notifications, the recipient address.

These fields are stored in the site’s database, so changing them needs no code deployment.

Which parts cannot be edited in the admin?

The body — the main message text, for example “Tilauksesi on vastaanotettu ja sitä käsitellään” — comes from WooCommerce’s template files. It is not visible or editable anywhere in the admin. Changing body wording is a code change, which we implement on request.

How are the current texts being reviewed?

As suggested in the question, all current messages have been collected — and they are published directly on this page, in the review list below. For every email it lists:

  • the current subject, heading, and additional content exactly as configured on the live site;
  • the body text, rendered in Finnish with an example order (bodies are not visible in the admin);
  • whether the email is currently enabled and who receives it.

To improve an email, open it in the list, write your new wording, and send it back to us in any form — for example: “Completed order — Subject: …, Heading: …, Body: …”. Only the emails you reply about will be changed; everything else stays as it is.

Who receives which email?

To the customer: order on-hold, order completed, order refunded, payment failed, customer note, password reset, new account, and email-address confirmation.

To the store admin: new order, order cancelled, payment failed, and payment-gateway-enabled notifications.

Two customer emails — the processing-order confirmation and the customer’s cancellation notice — are currently switched off. The order-details and point-of-sale emails have no on/off switch at all; they are sent per event.

What did the review surface?

  • Several emails still have English text saved in live fields — for example the on-hold heading “Thanks for your order!” and parts of the customer-note, password-reset, and refunded-order emails. Customers currently receive these in English, so they are the first candidates for improved Finnish wording.
  • The completed-order body is already customized in Finnish (the course-material instructions), set up in code earlier.
  • The admin’s new-order email also contains PixelYourSite tracking data below the order details.

Do we have ALL messages, notifications and emails under Messages and WooCommerce?

Yes for everything customers and admins receive about orders and the course. The site keeps customer-facing texts in two admin homes — the site’s own Messages menu and WooCommerce → Settings → Emails — plus a short list of fixed interface strings.

What is managed under Messages?

  • Messages → Emails — all 14 course and admin emails: the welcome email with password setup (including the returning-customer variant), the continuation round invite, both expiry notices, the round 2/3/4 reminders, “Harjoituksesi ovat valmiina”, and five admin notifications. It also holds the three text fields of the Epassi/Edenred on-hold email, even though WooCommerce sends that email.
  • Messages → Notifications — the after-round notices shown in the tests area (one per round, following Test Management), the continuation-required message, and the all-tests-done messages.
  • Messages → Purchase Messages — the four thank-you / payment-pending / payment-failed cards shown after checkout.

What is managed under WooCommerce?

The 17 order emails published in the review list on this page. They are edited under WooCommerce → Settings → Emails and rendered in the site’s brand by the Kadence email-designer plugin.

  • Admin receives: new order (to jani@selkakuntoutus.fi), order cancelled, payment failed.
  • Switched off on purpose: the processing-order confirmation and the new-account email — the course’s own welcome email replaces them.
  • At WooCommerce defaults: completed order, invoice, on-hold, refunded, password reset.

What sits outside both?

  • The contact-form notification (the form on the Yhteys page) — managed in Fluent Forms’ own settings; it goes to jani@selkakuntoutus.fi. The Messages → Emails page lists it with a direct link.
  • The password-reset email — standard WordPress text.
  • System notices (password changed, payment gateway enabled) and security-log digest emails.

None of these are order or course messages, so nothing the customer needs is missing from the two admin homes.

Fixed interface texts (part of the code)

A small set of on-screen strings are written in the site’s code rather than in any admin page:

  • the sidebar countdown, “Kurssia on jäljellä X päivää”;
  • the continuation banner, “Haluatko jatkaa verkkokurssia kuukauden ajan?”, with its Kyllä/Ei buttons and the Jatka kurssia checkout button;
  • login-page error and 2FA labels, consent-modal texts, and form validation messages;
  • checkout strings, “Siirry maksamaan” and Etukoodi texts;
  • one English leftover, “Please fill the question first!”, shown in the tests area.

Any of these can be reworded in code on request, or made editable in the Messages menu if wanted.

Question 3 WooCommerce 19 November 2026

Payment Cancelled or Failed Notice on the Product Page

Client’s original question

“Where can I change this error message? Maksu peruutettiin tai epäonnistui, joten tilausta ei ole kirjattu. Voit yrittää uudelleen alla.”

When is this message shown?

The notice appears when a customer cancels the payment at the bank or payment window, or when the payment fails, and is returned to the online store.

The store then:

  • Redirects the customer back to the course product page instead of the order-received page.
  • Shows this notice above the product, so trying again takes one click.

No paid order is recorded, the course is not activated, and the customer is not charged.

Can this text be edited in the WordPress dashboard?

No. This exact notice is a fixed text in the course plugin’s code, so it does not appear in any dashboard editor. Changing its wording requires a small code change, which we would then deploy to the live site.

The similar text that IS editable

The dashboard also contains a related text with similar wording: “Maksua ei ole suoritettu”, whose body reads “Maksu peruutettiin tai epäonnistui, joten tilausta ei ole kirjattu eikä kurssimateriaalia ole lähetetty. Sinulta ei veloiteta mitään.”

That text belongs to the failed-order card shown in the order confirmation flow, and it can be edited without any code changes:

  • Log in to the WordPress admin.
  • Open Messages → Purchase Messages.
  • Edit the “Failed order — payment not received” card.

Summary

  • Notice above the product (this question): fixed in the plugin code — changing it needs a code update.
  • Failed-order card after checkout: editable in the dashboard under Messages → Purchase Messages.

If you would like different wording for the product-page notice, send us the preferred sentence and we will make the change and deploy it.

Important clarification

The two texts look alike but live in different places. Editing the dashboard card never changes the notice shown above the product, and vice versa.

  • Failed-order card text (dashboard) Editable in the dashboard
  • Product-page notice text Fixed in the plugin code — unchanged

Question 4 WooCommerce 19 November 2026

Continuation Course Payments: Paytrail vs. Epassi / Edenred

Client’s original question

“When user decide to continue program from basic course. How payment works, they naturally can pay via Paytrail and then with Epassi / Edenred. How logic goes on these different methods? How I confirm, that they have paid when paying with Epassi / Edenred?”

The short answer

Paytrail and Epassi / Edenred work on two completely different logics:

  • Paytrail is fully automatic. The payment is confirmed by Paytrail itself, and the course opens with no action needed.
  • Epassi / Edenred never notify the store that money has moved. The order waits on hold until you verify the payment and mark the order Completed in the WooCommerce dashboard. That single action grants the course.

Marking the order “Processing” is not enough: the course activation runs only when an order reaches the Completed status.

How the customer reaches checkout

When a participant finishes the last round of the basic course (rounds 1–3), the account page shows the continuation banner: “Haluatko jatkaa verkkokurssia kuukauden ajan?”

  • Clicking “Kyllä” adds the continuation course to the cart and takes the customer straight to the checkout page.
  • The same payment link is included in the access-window reminder emails, and the store owner receives an email notification that the participant wants to continue (“User X haluaa jatkaa ohjelmaa”).

At checkout the customer picks one of the three payment methods: Paytrail, Epassi, or Edenred.

Method 1: Paytrail — fully automatic

  1. The customer is redirected to Paytrail and pays with their bank or mobile payment method.
  2. Paytrail notifies the store both when the browser returns and directly from Paytrail’s servers. Whichever arrives first confirms the payment; a duplicate guard ignores the second notification.
  3. Because the course is a virtual product, the order completes itself immediately.
  4. The course then activates automatically: the customer’s account is matched (by billing email) or created, rounds 4–5 are unlocked, and the welcome and round-invite emails are sent.
  5. The customer lands on a success page with a one-click auto-login link into their account.

If the customer cancels or the payment fails, the store records a cancelled order, blocks the activation, and shows the customer a failure card with a retry link (see Question 3).

Method 2: Epassi / Edenred — manual confirmation

  1. Choosing Epassi or Edenred places the order on hold immediately, with the note “awaiting manual confirmation”. The cart is emptied.
  2. The customer sees a pending card: “Tilaus on vastaanotettu – maksua ei ole vielä vahvistettu”, and receives an email saying the credentials will be sent within 1–2 days of paying with the benefit. That email text is editable under Messages → Emails.
  3. The customer then pays in the Epassi or Edenred app. After that the store goes silent, by design: there is no callback or webhook, so WooCommerce never learns that the payment happened.

This is intentional: Epassi and Edenred are payment method options only, and the confirmation step is a human decision.

How to confirm an Epassi / Edenred payment

  1. Verify the money. Check the Epassi or Edenred merchant portal (or the settlement report) and match the payment by amount and date. Benefit-app payments carry no order number, so if two same-amount orders arrive on the same day, cross-check with the customer.
  2. Mark the order Completed. In the dashboard, open WooCommerce → Orders, open the order that is on hold, set the status to Completed, and click Update.
  3. That is the whole procedure. Completing the order activates the course automatically: the account is matched or created, rounds 4–5 are unlocked, and the welcome and round-invite emails go out.

Good to know

  • The access window starts when you confirm. On the live site the continuation course is configured so that its 21-day window starts at the moment the order is marked Completed, not at the moment the customer actually paid in the app. Verify and confirm promptly.
  • Cancelled orders stay blocked. If an order was ever set to cancelled or failed, completing it later will not activate the course; a safety flag then blocks the grant. Fresh on-hold orders are unaffected.
  • Nothing auto-completes in the background. The thank-you plugin’s order auto-complete feature is switched off on the live site, so an Epassi / Edenred order can never activate itself without your confirmation.
  • Two test orders are still waiting. Orders #4119 (Epassi) and #4121 (Edenred) from 12 November are on hold. They appear to be earlier test purchases and can be cancelled or confirmed deliberately. Note: the admin page of order #4119 currently opens blank; its details are still visible in the orders list.

Important clarification

The live dashboard currently saves the course window length as 1 day (both basic and continuation) under Tests → Settings, and that saved value overrides the intended 21 / 30 days. Until it is corrected, every confirmed continuation order would open with a one-day access window (“Kurssia on jäljellä 1 päivää”). Set continuation to 21 and the basic course to 30 before confirming real Epassi / Edenred orders.

Implementation status

  • Paytrail payments Fully automatic — no action needed
  • Epassi / Edenred payments Manual — mark the order Completed to grant access
  • Access window length setting (live dashboard) Needs correction — currently saves 1 day, intended 21 / 30

Question 5 Notifications 19 November 2026

When Is the “All Tests Done” Message Actually Shown?

Client’s original question

“When user see this message?”

Where is this message?

This message is one of the course notifications under Messages → Notifications in the dashboard. Those notifications are the short texts shown to participants inside their course account — one for each finished round, plus a few special program messages.

The entry called “All tests done (final message)” is the closing message a participant would see on the Testit tab after completing every test in the program. Its built-in text is:

Hienoa! Olet tehnyt kaikki tarvittavat testit.

(“Well done! You have completed all the required tests.”)

So when do participants actually see it?

With the site working exactly as it does today: never.

This message belongs to the site’s old, free pilot flow — the version of the course that existed before courses were sold online. In that old flow, finishing the last test simply ended the program, and this text was the closing screen.

What do participants see instead today?

Today the course is a paid product. When a participant finishes the rounds they have paid for, the account page shows a different message — the continuation message. It explains that the purchased rounds are complete and offers the next block with the “Jatka kurssia” button that leads to checkout (how the payment then works is covered in Question 4).

The continuation message is the entry named “Continuation required (round gap)” on the same Notifications page.

Is something wrong because this message is unused?

No — nothing is broken. The message is simply a kept fallback from the old flow:

  • While the course-sales mode is switched on — which it is on the live site — customers can only ever reach the continuation message.
  • If the sales mode were ever switched off — for example, if the course temporarily became free — old-style participants would again get this friendly closing text instead of a dead end.

Leaving it as it is causes no harm and needs no action.

Can it still be edited?

Yes. It works like every other entry on that page: open it, edit the text, and press Save. Clearing the field restores the built-in copy.

Just note: because customers don’t receive this message today, editing it has no visible effect on the site. If you want to polish an end-of-course text, the continuation message is the one real customers actually read.

Important clarification

“All tests done (final message)” and “Continuation required (round gap)” look similar but belong to different flows. Only the continuation message reaches customers today: it appears when the purchased rounds are finished and offers the next block for purchase. The all-tests-done message stays unused together with the old free-course flow.

The small grey description printed under the message inside the dashboard describes that old pilot flow. It is part of the admin page itself — customers never see it.

Implementation status

  • Continuation message (the real end-of-course message) In use — editable in Messages → Notifications
  • Changes to either text On request
